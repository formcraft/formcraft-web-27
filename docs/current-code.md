## How to keep this file up to date (for Claude Code)

After every change to the code, before committing:

1. **Status line** at the top: date, phase, tasks done.
2. **At a glance:** change a row if the stack, a version or a tool changed.
3. **File map:** add, move or delete entries so the tree matches the disk. Mark moves `(was …)` until the phase ends.
4. **How it works today:** rewrite the paragraph for every part whose behaviour changed. Describe what it does now, not what it used to do; the old behaviour belongs in the change log.
5. **Phase 0 checklist:** set the status of the task and of each problem it fixed.
6. **Change log:** add one row (newest first).
7. **Known issues:** add anything found but not fixed; remove what's fixed.

Write plainly. Name files and components exactly. Don't describe planned features here as if they exist.

## How it works today

### App shell and routes
`main.jsx` loads the global styles and renders `<App/>`; in production it also registers `public/sw.js`. `App.jsx` nests `ThemeProvider > AuthProvider > SiteProvider > CartProvider > BrowserRouter > Layout > Suspense(PageSkeleton)`. `routes.jsx` maps every path to a lazily loaded page (`page(name)`), wraps each in `PageGate` (keyed by `pageForPath` from `data/pages.js`), keeps the old redirects (`/shop`, `/portfolio`, `/services`, `/blog`, `/plans`) and ends with `NotFound`. `prefetchRoute(href)` starts loading a page's code when a header link is hovered, focused or touched.

### Page switches (`data/pages.js`, `SiteContext`, `PageGate`)
`PAGES` lists every page with its paths, group, `defaultOn` and `locked` (Home, Contact, Sign in and Admin can't be turned off). `SiteProvider` reads Firestore `settings/site` `{ pages: { key: bool } }` over the REST API (no Firestore SDK on public pages), caches it in localStorage, and exposes `isOn(key)`, `canSee(key)` (admins see everything) and `setPage(key, on)` (admin only; the rules check the `admin` claim). `PageGate` shows a hidden page to admins under a "Hidden from visitors" strip, and visitors an "opens soon" sheet. `useShowLink()` filters links: the header (`data/nav.js` + `filterNav`), mobile menu, footer, home doors and the new pages all drop links to hidden pages. Everything is on by default.

### Content (`data/content.js`, `useContent`, admin)
`CONTENT` defines the collections the admin can edit — products, templates, projects, developments, posts, courses, events — each with a starter-data loader from `src/data/` and a field list for the admin form. `useContent(name)` shows cached or starter items at once, then lists the Firestore collection over REST; if it has any documents they replace the starter data. Items with `active: false` are hidden from visitors (admins see them tagged "Hidden"). Lists are cached per visit (5 minutes) and in localStorage. Images in `images[]` can be public/images names, `{ name, alt }` objects or Storage URLs (`lib/images.js`, `Photo`).

### Admin (`/admin`)
Open to the team. **Permissions (owner, 2026-10-24):** everyone on the team has the same full access (claim `admin: true`, role "team"); the **owner** (claim `owner: true`, Emlyn Atochon, set only with `scripts/set-admin.js --owner`) is the only one who sees and changes **Team**. The limited roles `marketing` and `editor` still work, for later (e.g. blog writers). **The menu (2026-10-24 tidy), grouped by what the person came to do; each label is also its panel's heading:** Overview · **Leads:** Leads, Link builder · **Social media:** Social planner (was "Studio", renamed so it isn't confused with the Studio division) · **Website content:** Site text, then one panel per collection · **Records:** Orders, Donations, Members (read-only; was "Inbox") · **Settings:** Pages, Features, Site details, Animation timing (was "Motion"), Team (owner only). On phones and small tablets the side menu becomes one grouped "Admin section" menu, and in the header the admin icon moves into the phone menu below 480 px (five icons don't fit 360 px). **Leads is the one place for people who contacted us**, with one status list (`src/data/leads.js`: new, contacted, qualified, won, lost, closed); older values from the old Inbox lists still show until someone changes them. Quote rows show the budget and the number of drawings attached. **Inbox** (admin). Editors see only Studio, limited to drafts. The header shows the admin icon to anyone on the team.
- **Leads** (`LeadsPanel`, `LeadCharts`): messages, quotes, investor leads and subscribers (newest 500 each) plus contact clicks (newest 1000) in one list; filters (type, source, status, date range, search); a status per lead (new, contacted, qualified, won, lost); KPI tiles; SVG charts (leads per week, by source, top pages, campaigns) each with a table view; CSV downloads (filtered list, all subscribers) with a BOM for Excel and formula injection blocked.
- **Link builder:** tagged links (utm source/medium/campaign) for each platform and page, base from `SITE_URL`.
- **Site details:** WhatsApp, phone, email, address, hours, socials (`settings/site.details`); WhatsApp buttons appear only once a number is set.
- **Motion** (`MotionPanel`): time scales 0.5×–3× for the opening animation, the tear, the Home model build and the page reveals (`settings/site.motion`, `data/motion.js`). SiteContext sets `--fc-motion` and `--fc-motion-build` on `<html>`; `index.html` reads the cached copy (`fc-site-motion`) so the opening animation follows it from a visitor's second visit.
- **Sky and weather** (`SkyPanel`, `SkyPreview`, `src/data/sky.js`): a preview hero built from the real engines (drag the sun or moon, every weather scene, day or night, computer / phone / slow-phone budgets, reduced motion; preview choices are never saved) above the settings every visitor gets: what weather to show (Kampala's live weather or one fixed scene), rain amount, wind strength, and the sun-and-moon engine numbers in three groups (stars around the moon, letting go, clouds around the sun) with the owner's tuner numbers as the defaults. Sliders change the preview at once; Save writes `settings/site.sky` (every value clamped to its range by `mergeSky`, cached on the device as `fc-site-sky`). `Sky.jsx` passes the saved numbers to `useSkyDrag`, so the hero drag follows them; the weather, rain and wind settings drive the page heroes and the Home 3D model ("Weather in the heroes").
- **Team** (`TeamPanel`, owner only): add people by email (`team/{email}`, full access by default, or a limited role); `onTeamChange` / `claimTeamRole` set the custom claims once functions are deployed. The functions never give or remove `owner`, and the owner keeps full access even if their own entry is removed. Only the owner can write `team/*` (rules).
- **Features** (`FeaturesPanel`): on/off switches for the site's optional features (`src/data/features.js`): opening animation, email sign-up prompt, plant-a-tree button, Home 3D model (off = the 2D drawing for everyone) and the falling paper scraps (greyed out while the 3D model is off). Saved in `settings/site.features`, cached on the device (`fc-site-features`); `useFeature(key)` reads them. The opening animation runs before the app, so `index.html` reads the cached switch: a change reaches each visitor from their second visit. **Weather** group: a master "Weather scenes" switch and one per scene (partly cloudy, overcast, mist, rain, storm; clear day and night are always on); `sceneSwitches(features)` turns them into the shape the cloud's `fallbackScene()` takes, so a switched-off scene shows the nearest calmer one (storm → rain → overcast → partly → clear; mist → partly). They apply to the page heroes and the Home 3D model. Tested by `npm test`. The sun-and-moon and wind switches arrive with those features. Never switchable: cookie notice, accessibility, reduced motion, the 2D drawing, sign-in, Admin, page switches, security.
- **Copy** (`CopyPanel`): every piece of text in the copy register (`src/data/copy.js`), page by page in the order it appears, with search and filters (all, changed, drafts, near the limit). Each piece: the current wording with a counter against its limit, a size (Smaller · Standard · Larger) for headings and paragraphs, the built-in wording, and Save draft / Publish / Discard draft / Back to the original (buttons only where there's something to act on). Drafts go to `copyDrafts/{page}` (team only) and show on the real page with `?preview=draft` for signed-in team members. Publishing writes `copy/{page}` and a history entry (`copy/{page}/history`) in one batch; "Back to the original" deletes the edit. Only Home is in the register so far (copy step B adds the rest).
- **Studio** (`studio/StudioPanel`): see "Marketing Studio" below.
The older parts: **Overview**; **Pages** (switches, grouped like the site map); **Content** (one panel per collection: live list via `useCollection`, add/edit form built from the field list, photo uploads to Storage `public/content/<collection>/`, hide via "Show on the site", delete with confirmation, "Import the starter list" to copy `src/data/` into Firestore); **Inbox** (messages, quotes, investor leads with a status the team sets; orders, donations and members read-only). Nothing on this page can mark a payment paid.

### Site text (Admin → Copy)
Pages read their words through `useCopy(page)` (`src/hooks/useCopy.js`): `t(id)` gives the text as React elements, `t.str(id)` plain text for alt text and labels. The built-in wording lives in the register `src/data/copy.js` (id, section, kind, text, length limit). Published edits come from Firestore `copy/{page}` (public), read over REST by `src/lib/copyStore.js` once per visit and saved on the device (`fc-copy-<page>`); `Layout` starts the read as soon as the route is known. An empty edit means the built-in wording; an edit is clipped a little past its limit so even a direct database write can't break a layout. Markup is limited to `**bold**`, `*italic*` and line breaks (`src/lib/copyText.jsx`, no HTML). Size presets wrap the text in `.copy-sm` / `.copy-lg` (`components.css`). Page titles and descriptions are copy too (`metaTitle`, `metaDescription`): `usePageMeta` uses a published edit first, then `seo.js`, then the page's own text, and `scripts/seo-pages.mjs` reads published edits at build time (it says so and uses `seo.js` when the database can't be reached). The tagline is never in the register, and the rules refuse a `tagline` key. A first-time visitor can see edited text swap in a moment after the page appears; pre-rendering will remove that.

### Funnel (L3)
`lib/attribution.js` keeps where a visitor came from (utm tags, which click id was present but never the id, referrer host, landing page): first touch (never overwritten) and last touch in localStorage `fc-source`. Every form adds `source` and `page` (`lib/forms.js`) and has a hidden honeypot field (`Honeypot`): if it's filled, the form pretends to succeed and saves nothing. With `VITE_FORMS_VIA_FUNCTIONS=true` every form goes through the `submitLead` function instead of writing Firestore directly. Email capture: `SubscribeForm` (inline, card, footer; consent required) writes `subscribers`; the card can offer a free download (`downloads` collection, edited in Admin → Content; template catalogue first, no file yet). `SubscribePrompt` slides up bottom right, above the plant-a-tree button, once a visitor has scrolled 55 % of a long page, at most every 14 days; it steps aside while the footer, a form on the page or a pop-up is showing. `/links` is the link-in-bio page; `/privacy` describes what is collected (legal parts TODO). `ConsentBanner` asks once; Analytics (`lib/analytics.js`) loads only after "Accept", in production, with a measurement id. `lib/track.js` counts clicks on phone, email, WhatsApp, social and `data-track="cta"` links into `clicks` (over REST, at most once per target per page view).

### SEO (L5)
`src/data/seo.js` is the single source: `SITE_URL` (`https://formcraftdesignconstruction.com`, the owner's domain; `SITE_URL` / `VITE_SITE_URL` override it for a test copy), organisation details, every route's title (≤ 60 chars), description (≤ 155), preview image, sitemap settings and noindex flag, and the JSON-LD builders. `usePageMeta(title, description, { image, noindex, canonical })` sets title, description, canonical, Open Graph, Twitter and robots tags; on static routes the values in `seo.js` win so the live page matches the pre-built HTML. After `vite build`, `scripts/seo-pages.mjs` writes a copy of `index.html` per route (and per starter product, template, project, post and development) with the right head, plus `sitemap.xml` and `robots.txt`; Firebase Hosting serves them through `cleanUrls`. Sample listings and private pages are noindex. `scripts/make-og.mjs` draws the 1200 × 630 preview cards in `public/og/` (paper, logo, page headline, title block).

### Marketing Studio (L6)
Admin → Studio plans social posts across an open-ended channel list (`data/socialPlatforms.js`: Instagram, Facebook, X, LinkedIn, TikTok, Pinterest and more; channels in `socialChannels`). Tabs: **Calendar** (month grid, agenda list on phones), **Queue** (today and upcoming, "Mark as posted"), **Generate** (fills the year with drafts from posting targets, the occasions calendar and the topic bank), **Bulk** (CSV import/export), **Channels** (targets, posting days, Buffer mapping), **Topics** (85 ideas in 13 pillars, `[placeholders]` where facts are needed), **Occasions** (54 from the Template Master Register with template codes FMC-MKT-HOL/AWR/DAY and care notes; Easter computed, Eid marked "confirm"), **Results** (leads per post and campaign via the tracked links' `utm_content` = post id). Posts go idea → draft → review → approved → published; approving needs every care note ticked, a date and a channel. `functions/studio.js` publishes approved posts through Buffer every few minutes once `BUFFER_TOKEN` is set (Pinterest by hand for now). Editors can only draft and send for review (`firestore.rules`).

### Firebase and data access
`config/firebase.js` loads Auth eagerly and Firestore/Storage/Functions on demand; the Firestore emulator is on 8081. Public reads use `lib/firestoreRest.js` (it also passes the server's `Date` header to the sky clock). Forms (`lib/forms.js`): `sendMessage`, `sendQuote` (+ drawing upload), `sendInvestorLead`, `sendInterest` (sign-ups, course and event places, newsletter → `messages` with a `[topic]` subject). Rules: content collections (products, projects, events, courses, templates, developments, downloads, posts) are public read, written by admins and marketing; `settings/site` public read, admin write; `settings/studio` team only; `copy/*` public read, team write (fields checked, no `tagline`, server time), `copyDrafts/*` team only, `copy/*/history` team read and add-only; `team/*` written by the owner only; leads (`messages`, `quotes`, `investorLeads`, `subscribers`) anyone creates with checked fields (incl. `source` map and `page`), marketing reads and sets status; `clicks` anyone creates (bounded fields), marketing reads; `team` admin only (members read their own); Studio collections by role (`isEditor`, `isMarketing`); members approved by admins; donors read their own `donations`. Storage: `public/content/**` and `public/social/**` for the team, quote drawings readable by marketing.

### Scene: sky, hills, trees, motifs
Every page hero sits under one shared sky (`Sky.jsx`, drawn by `PageHero` behind the hills): a gradient from `--sky-top` to `--sky-mid` with a glow at the horizon (`--sky-glow`, `--sky-glow-2`, `--sky-band`); the night edition adds ~300 fixed stars and 12 slowly twinkling ones (`starField` in `sceneGeometry.js`, seeded per page, off with reduced motion). The sun or moon (`SkyBody`) lives in `Sky.jsx` too. `PaperLayers` draws the paper landscape on top (two soft clouds by day; the old birds and per-scene stars are gone). The **sun (day edition) or moon (night edition) follows Kampala's clock** (`lib/skyClock.js`: sunrise 06:45, sunset 18:55 EAT, corrected by the server time when known): it rises on the left, is overhead at noon/midnight and sets on the right. It's placed in screen space so it's always in view, and rests low and rust-coloured when it's below the horizon. **Trees** (broadleaf, umbrella acacia, cypress and banana) are cut from the same sheet as their hill: small on the middle hills, a belt on the near hill and two big ones framing the front. Motifs per page: `design`, `construction`, `precast`, `workshop`, `plots` (template homes on pegged plots), `estate`, `forest` (staked saplings in front of grown trees), `academy`, `market`; others use the `city` skyline. With no saved choice, **the edition itself follows Kampala's clock** (day 06:45–18:55) and switches at dusk and dawn.

### Wind in the trees (Sky 2)
Every tree row in the page heroes (mid, near and front hills) is split into three groups by x (`groupTrees` in
`PaperLayers.jsx`; `plantTrees` now returns each tree's base point and size). Each group is its own small SVG (`TreeRow`),
so a sway is a compositor transform instead of a repaint of the whole hill; the two shades alternate by sub-shape
index across the row exactly as before, so the drawing is unchanged (compared pixel by pixel with motion frozen; only
the trees' own soft shadow differs). The groups are placed with container units (`.paper-layers { container-type:
size }`, `--u: max(100cqw / 1440, 100cqh / h)`, the way "xMidYMax slice" scales the layers), so they're right in the
pre-built HTML before any JavaScript. They `skewX` around their base line: a lean of 0.4° × wind plus ±1.6° (front),
±1.8° (near; 2.6° on phones), ±1.4° (mid) × wind (the cloud's review numbers), on 5.3 / 6.1 / 7.4 s periods. Gusts (wind ≥ 0.6) every 8–20 s add a 2.5 s bend that
starts on the right (easterly wind) and reaches the other thirds 0.35 s apart (`animation-composition: add`). Wind comes
from Admin → Sky and weather (`sky.wind`, 0–2) and Admin → Features "Wind in the trees"; calm, switched off or reduced
motion means no animation. Phones (≤ 600 px) keep the far row still; below 1260 px the front row (cropped off screen) doesn't animate; browsers without `animation-composition` get no gusts. Motif trees (forest, workshop…) stay static.
Clouds drift with the wind (`pl-wind-drift`: leftwards at 4 units/s × wind across the drawing, wrapping with a 1 % fade, starting from where they're drawn) and construction puffs lean downwind; calm, they rest.

### Weather in the heroes (Sky 3)
`useWeather()` (`src/hooks/useWeather.js`) decides each hero's scene, first match wins: a `?sky=rain&wind=1.5&budget=phone`
link or the team's Sky tester (this tab only, sessionStorage `fc-sky-test`) → Admin → Sky and weather's fixed scene →
Kampala's live record `stats/weather` (only with the `liveWeather` switch, off until functions are deployed) → clear.
Admin → Features' scene switches then swap a switched-off scene for a calmer one (`fallbackScene`); with "Weather scenes"
off it's always clear. It also returns the wind (Admin slider, or the live wind via `windFromMs`, at least the scene's
minimum: a storm is windy) and the rain amount. `Sky.jsx` draws it with `Weather.jsx`: the scene's wash under the
stars (full over the open sky, under a fifth of it behind the words); then the mist laid over the far hills, the cloud
ceilings, the storm's two rows and the fair-weather clouds; in front of the hills, strips of tracing-paper mist and the
rain canvas (its gap round each line of words, and a mask thinning it on the text side).
**Paper look (owner's references, 2026-10-25):** every cloud is cut paper (`PaperArt.jsx`, shapes in
`sky/weatherShapes.js`): a cool shade sheet, a lit sheet laid on it with a thin shadow under its edge, curled highlights,
and the site's paper grain (`public/textures/paper.webp` as an SVG pattern, multiplied). Cumulus clouds have round bumps,
small lobes underneath and sometimes a wisp; overcast, rain and storm have cloud ceilings with round lobes; the storm
adds two rows of heavy cumuli (lighter behind, darker in front), a soft glow inside the front row, and paper lightning
bolts that fade in and out one at a time (≥ 9 s apart, never a flash); mist is three strips of tracing paper with soft
torn tops sliding slowly across the hills. Tokens: the `--cloud-*` lit/shade pairs, `--paper-grain-*`, `--bolt`,
`--mist-sheet` / `--mist-edge` in `tokens.css`.
**Around the words:** `useHeroSize` also measures the hero's words (crumbs, logo, title, lead, buttons; the sheet number
as decoration) and the shapes are placed around them: clouds take the first free spots, the storm rows sit to the right
of the words (or along the top edge above them on phones, or not at all when there's no room), bolts only where they
touch no words, ceilings stop above the first words, mist strips lie below them. The weather contrast check passes on
every page, scene, edition and size.
**Smooth:** everything that moves is its own small layer that's only moved or faded (each cloud and mist strip is its own
`<svg>`; the glow and each bolt fade on their own layers; the rain canvas has its own layer), so the paper, its shadows
and grain are painted once. The hero's own two day clouds (`PaperLayers`) are paper cumulus too and drift on their own
wrapper (`.pl-cloud-drift`). Behind cloud the sun's ring pulse is stopped (it can't be seen and would repaint the sun). It also sets on the hero: `data-weather`, how many
of the hero's own two clouds stay (`data-puffs`), wet hills in rain (`data-wet`), fewer stars and a dimmer sun or moon
(`--sky-stars-k`, `--sky-body-k`). The trees sway with the scene's wind. Pre-rendered pages show the clear sky; the scene
fades in after hydration. The glow and rain (`useWeatherMotion.js`) run only while the hero is on screen and the tab is
visible; reduced motion draws one still frame of rain and no glow or drift.
**Sky tester** (`SkyTester.jsx`): a "Sky" tab at the bottom left for signed-in team members (and everyone in
`npm run dev`), loaded on demand so visitors never download it: weather Auto or any of the six scenes (switched-off ones
marked "(off)"), rain amount, wind slider and "Gust now", day/night, phone budget, Reset, and the live-data status. Closed,

**Home 3D:** with Features "Weather on the 3D model" and "Weather scenes" on, `HotelScene` passes the same scene to the
model (`env.weather`: kind, wind, rain amount; the cloud's `hotel/weather3d.js`: leaves flutter, rain, dimmer light) and
later changes go through `setWeather` without a rebuild.

### Pre-rendering (L5, ideas #20)
Every public page is built to finished HTML: `npm run build` runs `vite build`, then a server build of the same app
(`vite build --ssr src/entry-server.jsx --outDir dist-ssr`), then `scripts/seo-pages.mjs` (one HTML file per page with its
own head), then `scripts/prerender.mjs`, which renders each of those pages with React (`entry-server.jsx`: the same
`AppTree` as the browser, a fixed address, every page's code loaded up front through `lib/pageRegistry.js`) and writes
the result into `<div id="root">`, with `<meta name="fc-prerendered" content="/studio">` in the head. In the browser,
`main.jsx` first loads the page's code and the starter content (`preloadPage`, `preloadStarters`; adopting a page whose code
was still loading made React throw the HTML away and redraw it from the skeleton), then **hydrates** (React adopts the HTML instead of drawing it again, so nothing flickers or replays); a mismatch is
logged as `[hydration] …` and fails `npm run check` ("Hydration mismatch").
- **Matching the build:** anything that depends on the visitor's device stays out of React's first render
  (`src/hooks/useHydration.js`: `useIsHydrating`, `useDeviceState`): the cart, cached page switches, contact details,
  motion and features, cached content and copy edits, stats, the cookie answer, the sky clock and the 3D level all show
  their build-time defaults first and the device's values straight after. Edition-dependent markup is the same in both
  editions and the CSS picks (the switch's two icons, the footer's "day/night edition", the stars, hidden by day); the
  sun or moon appears after hydration (it rises in anyway).
- **Reveal:** content is visible by default; only content below the screen waits to slide in (`useReveal`), so the
  pre-built page shows at once. After a page change inside the site everything slides in as before.
- **Other addresses:** Hosting serves `index.html` (Home's HTML) for unknown addresses and the service worker uses it
  offline: a head script in `index.html` hides HTML built for another address (`.fc-stale`), and `main.jsx` clears it
  and starts fresh.
- **Styled from the first paint:** each page's own stylesheets are linked in its HTML head (from Vite's manifest, `build.manifest`, read by `prerender.mjs`); before, they came with the page's code, so the pre-built page painted unstyled and jumped into place (CLS up to 1.0 on Home, 0.2 on detail pages).
- **Not pre-built:** private or address-dependent pages (checkout, order confirmed, account, sign-in, admin, thank-you).
- **Page switches:** pages switched off in Admin → Pages aren't pre-built (the build reads `settings/site` over REST,
  with a Referer for a key restricted to the domain; when it can't, every page counts as on and the build warns;
  `npm run build:deploy` stops instead). A page switched off after a build keeps its old HTML
  until the next build and deploy.
- **Measured** (slow phone: 4× CPU, 1.6 Mbps, 150 ms; returning visitor; median of 3): the headline is on screen
  1.2–1.5 s sooner (Home 3.1 → 1.8 s, Studio 3.3 → 2.2 s, Stores 3.0 → 1.6 s, Contact 3.1 → 1.5 s); Home's largest
  paint 4.6 → 2.0 s. Lighthouse's mobile score barely moves, because it measures a first visit, where the opening
  animation covers the page for ~5 s either way. Page HTML: Home 30 kB, Studio 56 kB compressed (torn edges written
  as compact relative paths, pixel-identical). Main JS 85 kB gz.

### Moving the sun and moon (Sky 1, ideas #22; the owner's secret)
Visitors can drag the sun (day) or the moon (night) around any page hero's sky; nothing on the site mentions it, the
only clue is a soft glow when a mouse passes over it. `useSkyDrag` (`src/components/scene/useSkyDrag.js`) connects the
cloud session's engine (`sky/skyPhysics.js`, the owner's tuner numbers) to the page: a press anywhere on the hero
within 1.6 × the disc's radius picks it up, the pointer is followed on the window, an invisible `.sky-grab` handle
over the body (above the hero text) stops a finger there from scrolling the page, and `requestAnimationFrame` runs
only while something moves. At night the stars are drawn on a canvas (same seeded positions, sizes, brightness and
horizon fade as the old SVG; the 12 twinklers stay SVG and move along) and part around the moon; by day the paper
clouds (`.pl-cloud`) drift aside from the sun. On release the body rests 1.5 s, then glides home. The field is settled
before the first draw, so nothing jumps at the first touch. The moon shows its real phase (`sky/moonPhase.js`): the lit
part over a faint copy, turned toward the sun as on the equator. It's a paper-cut moon (`sky/moonArt.js`, `PaperMoon` in
`PaperArt.jsx`, after the owner's reference): a cream top sheet with the seas cut out where they really are, a taupe
sheet under it with their deepest parts cut out, a grey-brown bottom sheet, a few punched craters, each sheet shadowing
the holes below, and the paper grain. The sun is a paper disc with a lifted lit sheet and the grain. Reduced motion: drag only, stars and clouds
still. Admin → Features: "Move the sun and moon" and "Stars and clouds make way".

### Opening animation (`index.html`)
Inline CSS and two small scripts, so it paints before the app's code arrives. The head script picks the edition and a mode: **full** on a first visit, **quick** on later visits, **none** again in the same session (sessionStorage `fc-intro`, localStorage `fc-intro-seen`), **fade** with reduced motion, never for bots (`navigator.webdriver` or crawler user agents). It also reads the cached Admin → Motion timing (`fc-site-motion`) and sets `--fc-motion`, `--fc-motion-build` and `--fci-k`. Full: a drawing sheet (paper texture, grid, border, a perforation near the top) → the FC mark fades in slowly (0.8 s) and pulses like a stamp at 0.8 s while "Designing spaces. Empowering communities." appears word by word → the mark glides to the header logo's exact position (the real logo is hidden with `.fci-hold` until then) → **the sheet is ripped off from the left**: the tear runs along the perforation (rAF, ~1.3 s at 1×), the torn part (`.fci-sheet-a`, clipped left of the tear front) swings down around the front while the rest (`.fci-sheet-b`) stays attached and the perforation is still drawn to its right, then the whole sheet falls away and the stub lifts off. ### Home hero: 3D model or 2D drawing
`HotelScene` is a fixed layer behind the page. **The background shows first**: `--hotel-bg` (the 3D scene's own paper colour) plus one paper grain (`.hotel-scene-grain`, the site texture at its 384 px tile, multiply by day and soft-light at night) drawn at the screen's own resolution. Then one of:
- **3D** (most devices: `full`, `standard`, dev-only `ultra`): after the opening animation has gone (`introDone()`) and the browser is idle, the edition's script loads (`hotel/hotelDay.js` / `hotelNight.js`) with the baked paper textures. It draws at the screen's own sharpness (pixel ratio up to 2, `standard` up to 1.5, antialiasing only below 1.5×; `standard` also shrinks shadow maps; `ultra`: ≥ 2×, 4096 px shadows, paper drawn in code). It is compiled with everything visible, then **builds itself** (`hotel/build.js`): the torn backdrop sheets rise one by one, the board settles, the hotel goes up floor by floor (pieces drop in and settle, tall walls grow alongside), greenery grows from the ground, night lamps pop on; ~6 s at 1× (Admin → Motion "Home model building itself"), hurried if the visitor scrolls away or touches the model. Lights are never hidden (that would recompile shaders); the first frame skips the shadow pass so the first-use shader work is split over two frames. When done it sets `data-hotel-built` (labels fade in) and the paper scraps start falling. A slow idle turn (±9°) eases in after the build.
- **2D** (the slowest devices only; `Hotel2D.jsx`, `hotel2dGeometry.js`): the same model projected through the same hero camera as inline SVG — torn backdrop sheets, the hotel shaded by face with cast shadows, cutaway rooms, the "in design" wireframe bays as 1.25 px non-scaling lines, board, contour layers, greenery, figures; night windows, moon and stars. Its own ~5.8 s build (scaled by `--fc-motion-build`) and a soft scroll parallax (`--h2-y`). Colours from the `--hotel-*` tokens. ~100 kB of markup.

**Levels (owner, 2026-10-24: 3D for most devices, 2D only for the slowest).** `guessLevel()`: no WebGL / WebGL2, software graphics, the oldest phone GPUs (Mali-4xx, Adreno 3xx, PowerVR SGX, VideoCore), ≤ 1 GB memory or 2G → `2d`; reduced motion (model held still, no build), Save-Data, 3G, ≤ 4 GB, Mali-T / Adreno 4xx–5xx, or a small screen with < 6 cores → `standard` (pixel ratio up to 1.5, 1024 px shadows); else `full` (up to 2×). A remembered result (`fc-hotel-level`, 30 days) wins. **Frame check** (after the build and 120 settled frames): below ~30 fps the pixel ratio steps down by 0.5, never below 1× (remembered as `standard`); only if frames stay below ~20 fps at 1× does it hand over to the 2D drawing (remembered). In `npm run dev`, a **preview switch** (bottom left) forces Auto / Ultra / Best / Mid-range phone / Slow connection / 2D drawing (`fc-3d-preview`, never read in production; sets `env.fixed` so the frame check doesn't switch).
**Built in steps.** `createHotelScene(canvas, env)` is async: it yields between the materials, hotel, cutaway, trees, backdrop, lights and camera steps and stops early if the page is left (`env.signal`); shaders compile with `compileAsync` before the first frame.
**Views and zoom.** `HotelControls` is a slim vertical icon rail at the top left of the hero, shown once the 3D is ready: Front, Back, Cutaway, Site, zoom in/out, reset (names show beside the icons on hover or focus and are the buttons' accessible names). Pinch and Ctrl+wheel zoom too (0.6–1.6×, sprung); the plain wheel scrolls the page. The drag hint hides on phones once the model is ready.
**Paper scraps.** Their own seeded random; 6 near pieces (4 on phones) fall through the hero view and respawn there, the rest further back; 35 % rust / 30 % navy / 35 % white by day, rust and white at night; 0.35–0.7 m/s.
**Debug flag.** `?hoteldebug` logs each build step's time and exposes `window.__hotelDebug`.

### Security (L2 groundwork)
`firebase.json` sends security headers on every response: `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: SAMEORIGIN`, `Permissions-Policy`, HSTS, and a **report-only** Content-Security-Policy (switch to enforcing once the console shows no reports; see `docs/owner-checklist.md`). `cleanUrls` serves the pre-built pages. `functions/index.js` (deploy needs Blaze): `submitLead` (callable; validates and writes messages/quotes/investorLeads/subscribers with honeypot, per-connection and per-email rate limits in `rateLimits/`, App Check enforced when `ENFORCE_APP_CHECK=true`), `claimTeamRole` (sets a signed-in member's role from `team/{email}`), `onTeamChange` (keeps claims in step when an admin edits `team`). `AuthContext` exposes `role`, `isMarketing` and `isEditor`, and calls `claimTeamRole` after sign-in when `VITE_FUNCTIONS_ENABLED=true`. `scripts/set-admin.js` also takes `--role marketing|editor`.

### Caching
`public/sw.js` (production only, `VERSION` `fc-2026-10-24c`): on install it precaches the home page and the assets it references; the page also posts the list of resources it loaded (`main.jsx`), so those get cached too. Pages network-first with an offline copy (40 pages kept) and an offline fallback page; `/assets/` cache-first; fonts, textures, logos and images stale-while-revalidate (images capped at 160). Firebase Hosting: `/assets`, fonts and textures cached for a year (textures are versioned with `?v=`), logos 30 days, images 30 days + stale-while-revalidate, `index.html` and `sw.js` no-cache. Content and page switches are cached in localStorage.

### Paper and textures
`public/textures/*.webp` are generated by `scripts/make-textures.py`: 768 px seamless tiles with pulp clouds, a coarse cold-press tooth lit from the top left, long fibres, short hairs, flecks and bark inclusions; shown at 384 px (`--tex-size`) so the grain stays sharp. The tint overlays in `tokens.css` were thinned so the texture shows. Each sheet's torn top edge (`TornEdge`) is now cut from the same textured paper (`--edge-tex`, clipped to the tear in pixels) with a pale fibre line and loose hairs along the tear.

**The 3D model's paper** (`scripts/make-hotel-textures.py`, ideas #11) is sized in metres of wall: the 1024 px tile covers 4 m (the scenes' `uvScale` tile), so the pulp clouds are 0.5–1.5 m, the cold-press tooth 4–10 cm and the fibres 1–1.5 cm wide. It writes `hotel-paper.webp` (1024, desktops), `hotel-paper-512.webp` (phones) and `hotel-normal-512.webp`, a **normal map** of the same relief. The scenes swap their paper bump for it just before compiling (keeping each material's relative strength: walls full, leaves about half, the board a trace), so light catches the tooth at any distance; the old bump map never showed once the model was on screen. Two dials at the top of the script: `RELIEF` (normal-map strength, 0.4) and `CONTRAST` (colour variation, 0.6, std dev ~9 of 255 but at a size that shows). The owner found the first pass (1.4 / 1.0) too much, then 0.6 / 0.7 still a little strong. `HotelScene` loads them with `?v=TEX_V`; bump `TEX_V` after regenerating. The dev-only `ultra` level still draws its paper and bump in code.

### Motion rules
Two kinds of motion. **UI motion** follows `.claude/skills/emil-design-eng`: curves `--fc-ease-out` (enter/exit, press, hover), `--fc-ease-in-out` (moving on screen) and `--fc-ease-drawer` (drawers and sheets) in `tokens.css`; buttons, icon buttons, the Links buttons and the plant-a-tree button give a little when pressed (`scale` .94–.98 on `:active`, 160 ms); hover lifts and image zooms only on devices with a real pointer (`@media (hover: hover) and (pointer: fine)`), so taps on phones don't leave things stuck "hovered"; cards lift in 250 ms; the cart drawer slides with the drawer curve; the plant-a-tree pop-up grows out of its corner (`transform-origin: 100% 100%`, 200 ms); the cookie banner and the subscribe slip come in within 300–350 ms. **Storytelling motion** (the opening sheet, the Home build, section reveals) keeps `--fc-ease` and the Admin → Motion timing. With reduced motion, movement stops but reveals still fade in (200 ms).
